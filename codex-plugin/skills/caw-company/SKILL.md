# caw-company — 企業・業界研究

就活モードの企業・業界研究部スキル。公開情報を構造化して志望動機・面接の素材にする。

## いつ使うか

- `/caw-company` を実行したとき
- 「○○社について調べて」「企業研究して」「業界研究」「この会社どう？」と言われたとき

`.company/`（就活モード）が無ければ `/caw` で就活トラックを促す。企業・業界研究部が未作成なら作成を提案する。

## はじめてモードを尊重する

このスキルを実行する前に `.company/AGENTS.md`（Claude Code では `CLAUDE.md`）を読み、冒頭に `> 運用モード: はじめて` があれば、`caw` skill の「はじめてモードの挙動」を全応答に適用する：**平易な日本語**で話し、専門用語（IR・選考フロー・求める人物像 等）は初出で 1 行説明を添え、各ステップの最後に**「次はこれをしましょう」を 1 つ**だけ提示する。

## ワークフロー

### Step 1: 対象を確認

企業名（または業界）を確認。複数社なら 1 社ずつ進める。

### Step 2: 情報収集

- **web 検索 / MCP が使える場合**: 公式採用ページ・IR・最近のニュースを取得する。**一次情報（公式採用ページ・IR）を優先**
- **使えない場合（フォールバック）**: ユーザーに採用ページ URL や説明会資料の貼り付けを依頼し、それを材料にする
- 口コミ・評判は参考に留め、**出典を併記し断定しない**

### Step 3: 構造化して保存

`companies/<企業名>.md` に次の見出しで構造化する：
- 事業内容・主力製品/サービス
- 強み・弱み・最近の動き
- 競合・業界内のポジション
- 求める人物像（採用ページの記載）
- 募集職種・勤務条件（職種・勤務地・給与レンジが分かれば）
- 選考フローと締切（エントリー → ES → Web テスト → 面接 …）
- **自分との接点**（自分の経験・価値観のどこが刺さるか）

取得日を併記する（採用条件は年度で変わるため）。

### Step 4: 志望動機の素材を抽出

「自分の経験のどこがこの企業に刺さるか」を 2〜3 点まとめ、`caw-es`（志望動機）や自己分析部が再利用できるようにする。

### Step 5: 業界比較（任意）

複数社・業界全体を見るときは `companies/_industry/<業界名>.md` に比較表（事業領域・特徴・志望度メモ）を作る。

### Step 6: 選考フローを秘書に共有

選考フロー・締切は秘書（`secretary/todos/`）の選考スケジュールにも反映を提案する（抜け漏れ防止）。

## 重要な注意事項

- **一次情報（公式採用ページ・IR）を優先**。口コミは出典併記・断定しない
- 古い情報に注意（募集要項・採用条件は年度で変わる）。取得日を併記する
- 企業の非公開情報・個人情報はローカルに留める
- 成果物は top-level `companies/` に置く
