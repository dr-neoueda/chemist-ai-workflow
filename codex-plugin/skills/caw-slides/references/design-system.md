# caw-slides デザインシステム

SVG-first で研究発表スライドを描くときの**オーサリング規約**。土台は PPT Master のデフォルト出力
（© 2025–2026 Hugo He, MIT。`vendor/NOTICE.md` 参照）で、**日本語の化学スライド向けに調整**してある。
特定の研究室のロゴや色は入れない。

規約の多くは `scripts/deck_chrome.py` と `scripts/deck_parts.py` に実装してある。**手で座標を書かず、この部品で組む**
（`references/sample_deck.py` が手本）。規約を破りにくいことが部品を使う理由である。

> **§0 最優先**：スライドは文章を読ませる媒体ではなく、**図表で瞬時に伝える視覚装置**。数値・比較・時系列・
> 工程・関係は図表で示す。1 スライド 1 メッセージ。本文の箇条書きが 3 行を超えたら表か図にする。

---

## 1. キャンバス

- `width="1280" height="720" viewBox="0 0 1280 720"`（16:9、単位は px）。pptx では 1 px = 0.75 pt。
- 余白は左右 80 px。本文の右端は 1200 px まで（`check_margins` が検定する）。
- 全面の背景 `<rect>` は描かない。ページの白はスライドマスターがそのまま出る。

---

## 2. 定型に見える構造物を置かない（最重要）

全ページに機械的に同じ構造物が並ぶと、AI が作った定型の資料に見える。次のものは**使わない**。

| 使わないもの | 代わりに |
|---|---|
| 強調帯の左の縦アクセント線 | 1 px の枠線＋ごく薄い地（§5） |
| 見出し・小見出しの左の縦棒 | 四角マーカー（`column_head`） |
| 二言語キッカー（「日本語 · ENGLISH」） | 何も置かない |
| タイトルの下のリード文（その枚の主張の 1 文） | 主張は本文・図・強調帯で示す |
| 全ページの左下の注記（プロジェクト名・著者・年） | 右下のページ番号だけ |
| 固定幅の枠（右に大きな空きが出る） | 幅は中身に合わせる（`callout` が自動で行う） |
| 文中の全角ダッシュ「—」 | 句点で切る、助詞でつなぐ、コロン、括弧 |
| テキストの背景の灰色パネル・カード | 白地に直接置き、線と余白で区切る（§5） |
| ページ切り替え効果 | 付けない（`build_deck` が切る） |

⚠️ **「AI 作成感を減らす」を色数の削減に読み替えない。** 減らすのは定型の構造物であって色ではない。
紺＋グレー＋1 色に絞ると質素に見える。青・金・赤・緑は意味の色として使い続ける。

---

## 3. 見出し・本文・フッター

| 部品 | 関数 | 内容 |
|---|---|---|
| 表紙 | `cover(lines, authors=, affiliation=, venue=)` | 帯＋36 px のタイトル＋線＋著者・所属・会議名 |
| 見出し | `header(title)` | アクセントタブ（40×6）＋28 px のタイトル＋線（y=140） |
| 本文の頭 | | **線の直下**（y≈156〜180）から始める。線と本文のあいだを空けない |
| フッター | `footer(n, total)` | 右下の「n / N」だけ。補足の枚は `app_footer(k)` |

**タイトルは短い名詞句**にして、その枚で扱う対象を名指す。
❌「ステップ 3」「結果」「三重項が単項の約 300 倍だった」 → ✅「影響範囲」「押しの向き」「励起状態の寿命」

## 4. 色

| 役割 | 定数 | HEX | 用途 |
|---|---|---|---|
| 紺 | `NAVY` | `#16283D` | タイトル・見出し・表の上端の線 |
| 青 | `BLUE` | `#1F6FEB` | 中立の強調 |
| 金 | `GOLD` | `#B9791F` | 注意 |
| 赤 | `RED` | `#D6455D` | 警告 |
| 緑 | `GREEN` | `#2E9E6B` | 良好 |
| 本文 | `BODY` / `DARKBODY` | `#47535F` / `#334452` | 本文 |
| 灰 | `GREY` | `#8894A2` | 文献・注・ページ番号 |
| 線 | `DIVIDER` / `HAIRLINE` / `FRAME` | `#D8E0E8` / `#EDF1F5` / `#E3E9F0` | 区切り線・行間の線・図の枠 |

色は意味を運ぶ。列見出しと行頭のマーカーは同じ色にそろえる。

## 5. 低塗り

- **本文は白地に直接置く。** ブロックごとに灰色のカードで囲まない。2 カラムは見出し＋マーカー＋余白で分ける。
- 構造は軽い要素で作る：四角マーカー、番号バッジ（`deck_parts.badge`）、細い線、太字と色。
- **塗りは 1 領域に要点ボックス 1 つ**（`callout`）。データが密な枚でも 2 つまで。
- 要点ボックスは 1 px の枠線＋枠線の色を白へ 96 % 寄せた地（`wash()`）。`edge` で色を選ぶ。
- 塗りを許すのは、図の枠（白＋細い線）、表の 1 行（`table(highlight=)`）、実際のコードや入力のブロック（`#0F1B2C`）だけ。
- マーカーは 2 段階：列見出し `MARK_COLUMN = 9`、行頭 `MARK_BULLET = 5`。同じ大きさにしない。

## 6. 文字

### フォント
- 和文 `'MS Gothic','Hiragino Kaku Gothic ProN',Arial`、英数 `Arial`。`text()` / `bullet()` などが run を自動で分ける。
- 丸数字 ①②③ は Arial に無く豆腐になるので和文の run に置く（`mix` が自動で行う）。Δ・‡・≈ は Arial 側に置く。

### 大きさ
| 役割 | px | pt |
|---|---|---|
| 表紙タイトル | 36 | 27 |
| ページタイトル | 28 | 21 |
| 列見出し | 20 | 15 |
| **本文・表・囲み・図のラベルの下限** | **18.67** | **14** |
| 文献・細かい条件の注・ページ番号（`fine=True`） | 13 | 9.75 |

本文を描く関数は 14 pt を下限にかける。対象外にしたい注だけ `fine=True` を渡す。**最初からこの大きさで組む**（後から上げると全枚の配置が崩れる）。

### 上付き・下付き
- `text(x, y, "1700 cm^{-1}")`、`"H_{2}O"` と書く。`baseline-shift` の tspan になり、`build_deck` が pptx に復元する。
- Unicode の ₁ / ⁻ は使わない（`¹H` の ¹ だけ Arial にあるので可）。
- **1 行に 1 つの `<text>`** で書く。dy で行を積んだ `<text>` は 1 段落にまとまり、上付きを復元できない。

### 配置
- `tspan` を含む文字は左揃えにする。中央・右揃えは幅を誤測する。
- 中央揃えは `deck_parts.centred`（フォント 1 本・tspan なし）。添字を含む式は左揃えにする。

## 7. 図

- **数値や日付で形が決まる図は matplotlib で描く**（`scripts/fig_style.py`）。手描きの棒グラフは使わない。
  貼る箱の px をそのまま `fig_style.figure(w, h)` に渡すと、図の中の文字の大きさがスライドとそろう。目盛りは内向き。
- **値はデータファイルから読み、手で写さない。** 本文・表の数値も同じ。同じ量を 2 枚で使うなら関数を 1 つにする。
- **説明のための模式図を数値グラフに差し替えない。** 置き換えるのは数値で形が決まる図だけ。文字の表は SVG のまま（編集できる）。
- 図は `images/` に置き、SVG からは `../images/<名前>` で参照する。`deck_parts.figure` は縦横比を PNG から取る。
- 論文紹介は**原論文の図を主役**にする。切り抜きは図の部分だけで、キャプションや本文を含めない。図の下に文献を添える。
- 化学構造は頂点を計算して描く（六員環は頂点を計算して polygon に、芳香環は内接円に）。

---

## 8. 表・図形

- 表は `deck_parts.table`：上端の紺の線、灰色の列名、細い行間の線、薄い地の行は 1 行まで。
- 矢印は `deck_parts.arrow`（矢じりは塗りの三角形。`<marker>` は変換器を通すと安定しない）。
- 動画の置き場は `deck_parts.frame` で枠を描き、動画は `videos.json` で置く（SKILL.md 参照）。
- アイコンは図形で描く。`<use data-icon>` は使わない（アイコン集を同梱していない）。

---

## 9. SVG の制約（守らないと変換器が壊れる。`svg_quality_checker` が検定する）

1. 禁止：`mask` / `<style>` / `class` / `<foreignObject>` / `textPath` / `animate*` / `<script>` / `<g opacity>`。
2. 透明度は `fill-opacity` / `stroke-opacity`（`rgba()` 不可）。淡くしたいときは淡い色を使う。
3. 文字は raw Unicode（`→` `·`）。HTML の実体参照は禁止。XML の予約文字は実体で（`&amp;` `&lt;`）。部品は自動で処理する。
4. `transform` を文字に使わない。座標は `x` / `y` で書く（`assert_no_overlap` が測れないので違反にする）。
5. `clipPath` は `<image>` にのみ使える。

## 10. 検定が拾わないもの（必ず絵で見る）

| 拾えないもの | 確認の仕方 |
|---|---|
| 文字と画像の重なり、文字と枠の重なり | `assert_no_overlap` は文字どうしだけを見る。図を置いた枚は必ずプレビューの絵を見る |
| 図の中の文字の重なり・はみ出し | 画像の中身はどのゲートも見ない。絵で見る |
| 強調帯の文字のはみ出し | `callout` が高さと幅を検定して止める。部品を使わないと拾えない |
| プレビューの欠け | 1280×720 以外の画像は中身を隠す。`make_preview` は寸法を検定する |
| 枚を外した後の相互参照 | 「補足 3」のような本文の参照を文字検索で数え直す。番号は並びの 1 か所から引く |
| 同じ測定名の数値の食い違い | 同じ測定が複数の枚に出るなら、図の入力が同じ測定・同じ解析の版かを確かめる |

## 11. 内容の書き方

- **聞き手の予備知識で理解できる、確定した結果だけ**を書く。試行錯誤・訂正・「以前は」の経緯は書かない。
  やり直した結果の旧い枚は注記して残さず削除する。経緯は `caw-playbook` に残す。
- **公式の場の書き言葉**で書く。話し言葉や曖昧な表現は避ける。
  例：使ってきた → により追跡／合う → 一致する／ほぼ同じ → 差の数／だけ → のみ／「これまで」「これから」→ 中身を名指す見出し／「〜？」→「〜は何に由来するか」
- 見出しに人名を入れない（「結晶の DSC（1980）」のように中身だけ書き、人名は文献の行に）。
- **密度は実際に話せる量で作る。** 補助資料は質疑用であって発表の材料ではない。報告会は「研究テーマ→実験→計算」の主要な枚に絞る。

### 型
- **論文紹介（6 枚）**：①表紙 ②背景・系 ③機構 ④自作データ ⑤速度論・主要図 ⑥結論＋自研究への接続。
- 学会発表・報告会・講義の枚数は SKILL.md の表を参照。
