# caw-slides スタイルガイド — 化学研究発表向け PowerPoint 作成ルール

> 化学者の研究プロジェクトで実運用された 12 件のスライド（報告会・学会発表・研究紹介・修論）から抽出した実証済みルール。caw plugin に同梱されている `references/pptx_helpers.py` がこのガイドの規約をコード化している。

このガイドの位置づけ:

- **目的**: プロジェクター映え・編集可能性・視認性を最優先する研究発表スライドの設計仕様
- **対象 CLI**: Claude Code / Codex CLI / その他（CLAUDE.md / AGENTS.md / GEMINI.md いずれからも参照可）
- **このスタイルを変えたいとき**: 該当セクションを編集し、プロジェクトの `.company/presentation/CLAUDE.md` (or AGENTS.md) に反映する。`pptx_helpers.py` の定数も併せて更新

---

## 0. 絶対ルール — 文字数を極限まで減らし、図表で直感的に伝える

> **本ルールはこのガイドの他すべてのルールを上書きする最優先ルール。**
> スライドはテキストを読ませる媒体ではなく、聴衆に瞬時に意味を伝える視覚装置である。
> **文字で書こうとしているものは、ほぼ常に図・グラフ・表・スキームで置き換えられる。**

### 基本原則

1. **テキストは「解釈・結論」のみ**：数値・比較・時系列・プロセス・関係性・構造はすべて視覚要素で示す
2. **本文を書き始める前に、まず「これは図表にできないか」を 1 回考える**
3. **書いたあとに「この箇条書きは何かに置き換えられないか」を必ず再点検する**
4. **本文量で困ったらフォントを小さくせず、スライドを分割するか、内容を捨てる**

### 文章 → 図表 置き換え判定木

文章中に以下のパターンを見つけたら、対応する視覚要素に必ず置き換える：

| 文章中に見つけたら | 置き換え先 | 使う helper |
|---|---|---|
| 数値の列挙（3 個以上） | テーブル or バーチャート | `add_data_table` / `add_bar_chart` |
| 時間 / 濃度 / 温度に対する変化 | ラインチャート（散布線） | `add_scatter_line_chart` |
| 手順・プロセス（3 ステップ以上） | フロー図（ネイティブ矩形 + 矢印） | `add_flow_box` + `add_flow_arrow` |
| カテゴリ × 属性の比較 | テーブル | `add_data_table` |
| 概念の対比（2〜3 要素） | 左右 2 カラム or 3 カラムの shape カード | `add_shape_card` × n |
| 反応式・有機分子構造 | RDKit 描画（PNG embed） | `add_picture_fit`（RDKit `Draw` 出力） |
| 結晶構造・パッキング | 原図 or VESTA 出力（PNG embed） | `add_picture_fit` |
| エネルギーダイアグラム | matplotlib patches で線図 → PNG embed | `add_picture_fit` |
| タイムライン（先行研究の年表など） | matplotlib patches の水平バー | `add_picture_fit` |

### 量的な上限（守れない場合はスライドを分割する）

| 要素 | 上限 |
|------|------|
| **1 スライド内のテキストボックス数** | タイトル + 本文 + key-message band = **3 個まで**（補足ラベル 1 個まで許容、合計 4 個） |
| **本文ブロックの総行数** | **8 行まで**（▸ セクション含む） |
| **1 テキストボックス内の文字数** | **120 字まで**（英数字空白込み） |
| **1 行の長さ（本文）** | **35 全角字 / 60 半角字** まで（自動折り返しに頼らない） |

これを超えたら **スライドを分割するか、内容を図表に落とすか、書くのをやめる**。自動縮小（`TEXT_TO_FIT_SHAPE`）に頼って本文を 16pt 未満に落とすのは禁止。

### タイトルは主張形に書く

- ❌ 「結果」「考察」「方法」「実験」のような無味な見出し
- ✅ 「**Form I は 175 分で Form II に転移**」「**2θ = 10° の新ピークが反応開始 5 分で出現**」
- ✅ 「**B3LYP は活性化エネルギーを ωB97XD より 12 kcal/mol 過小評価**」

聴衆が **タイトル一覧を見るだけで主張が予測できる**ことを目指す。

### 何も置けない場合は捨てる

- 文章で書きたい内容が図表に置き換えられない場合、その内容は **そもそも口頭で話せばよい**（スライドは話を補助する道具）
- スライドに残すかどうか迷ったら捨てる。**読み手の認知負荷を下げる方が情報量を増やすより常に正しい**

### 自動チェック（実装済み・v1.4.0 以降）

`pptx_helpers.assert_text_minimal(slide)` を各スライドビルダー末尾で呼び、以下を自動検証する。違反は `ValueError` で生成停止（`assert_no_overlap` と同じ仕組み）。

- **テキストボックス数 ≤ 5**（タイトル + slide_number + 本文 + key-msg + 補足 1）。`split_2col` を使うときは `max_textboxes=6` を明示
- **本文総行数 ≤ 12**（chrome 3 + 本文 ~8 + key-msg）
- **1 ボックス内文字数 ≤ 120**

加えて `pptx_helpers.assert_title_assertive(title)` でタイトルが「結果」「考察」「方法」等の無味な見出しでないか lint する。意図的な総括スライド（「結語」「Conclusion」「Summary」）は blacklist 外で許容。

### 表とまとめスライドの作り込み（AI 作成感の除去）

実フィードバック（2026-05-20）で判明した「AI が作った感」を消す要点：

1. **表はセルを内容に密着させる（空白で AI 作成感が出る）**：セルの大きさに対して文字が少なく空白が大きいと、いかにも自動生成に見える。
   - `add_data_table` は **デフォルトで行高さを `max(font, header) × 1.8` に詰め、セル上下余白を 3pt** に絞る（v1.4.1+）。短い項目の 4 行表は ~1.6" に収まる
   - **表をスライド全幅に引き伸ばさない**。内容に見合う幅（例 10.6"）にして**中央寄せ**する。全幅 × 少文字 = 横方向の空白も AI 作成感の元
   - 行をどうしても埋めたいなら、空白を増やすのではなく**情報を足す**（列を増やす・各セルを具体化する）か、行高さを詰める
2. **まとめ / 結語スライドにも必ず図を置く**：recap を箇条書きテキストだけにしない。研究全体を 1 枚で要約する視覚要素（positioning 図＝精度 vs コストの 2 軸散布、概念スキーム、最重要 figure 等）を入れる。§0「図表で直感的に伝える」は結語スライドにも等しく適用される
   - 例: 「精度 vs コスト」の 2 軸 positioning 図に FF / DFT / MLIP を置き、MLIP を sweet spot として強調 → 講演全体の主張が 1 枚で伝わる
3. **コンテンツスライドは「図・表・グラフ + L1 + 支持本文」を基本構成にする**：視覚要素（図 / 表 / グラフ）を 1 つ置いて key-message band（L1）を 1 行添えるだけだと、視覚要素の周囲に大きな余白が残り「作りかけ」に見える。**§0 の「文字最小化」は「視覚要素 + 一行だけにせよ」という意味ではない** — 散文を削るのが目的で、スライドを空疎にするのが目的ではない。
   - **3 要素を必ず揃える**: ①図・表・グラフ（主役の視覚要素）②L1（key-message band = そのスライドの主張 1 行）③**支持本文**（視覚要素の読み方・主要数値・解釈）
   - 配置パターン:
     - **視覚要素が幅を埋めない**（中央寄せの chart / energy diagram / 縦横比の小さい原図）→ **視覚要素を左、支持本文カードを右**の 2 ゾーン
     - **視覚要素が横長で上部を占める**（全幅テーブル / waterfall 等）→ **視覚要素を上、支持本文カードを下**。tight 化した表は縦に縮むので、下の余白を支持本文で埋める
   - 支持本文 = ▸ セクション + ・ 2〜4 行。**L1（主張）とは別の情報**を持たせる（L1 = 結論、支持本文 = 根拠・読み方・補足数値）
   - テキストボックス数は chrome 2 + 支持カード 1 + L1 1 = 4 で `assert_text_minimal` 上限内
   - 例外: タイトルスライドは視覚要素なし・テキスト最小で OK（スパースが正しい）。フロー図のように視覚要素自体が画面を占めて情報を持つ場合も、短い文脈 1 行で足りることがある

### 図表構成要素は §0 の文字数上限の対象外（assert の override）

`assert_text_minimal` はテキスト shape 数・行数で §0 を強制するが、**フロー図の box ラベル・テーブル・`split_2col` の 2 カード等「図表の構成要素」も text shape として数える**。これらは散文ではなく図の一部なので、上限超過は誤検出。

- §0 の文字数上限が対象とするのは **散文テキスト（タイトル・本文ブロック・key-message）**
- 図表 helper が作る shape が多いスライドは、明示的に上限を上げる：
  - `split_2col` を使うスライド: `assert_text_minimal(slide, max_textboxes=6)`
  - フロー図（`add_flow_box` × N）スライド: `assert_text_minimal(slide, max_textboxes=N+3, max_total_lines=...)`（box ラベルが複数行なら行数も上げる）
- ただし**散文を図表 shape に偽装して上限を回避してはいけない**。図表構成要素として正当なものだけ override する

### 既存ルールとの関係

このルールはセクション 11（図表・ビジュアライゼーション）とセクション 12（スライドデザイン 7 原則）の **上位ルール**。両者が本ルールと矛盾するように見えた場合は、必ず本ルールが優先する。

## 1. スライドサイズ・基本設定

- **スライドサイズ**：言語・場面を問わず常に **16:9（13.33" × 7.5" / 33.9 × 19.1 cm）** を使用する
- **フォント（混在ルール）**：
  - 和文（日本語）：**MS ゴシック**
  - 英文・数字・記号：**Arial**
  - 同一テキストボックス内でも、日本語部分と英数字部分でフォントを使い分ける

## 2. フォントサイズ体系

| 用途 | サイズ |
|------|--------|
| タイトルスライドの大見出し（報告会番号など） | **72pt** |
| 強調大見出し・研究テーマ名 | **32pt** |
| スライドタイトル（各コンテンツスライド） | **28pt** |
| セクションヘッダー（▸ の直後） | **24pt** |
| 本文・箇条書き（最頻使用） | **20pt** |
| 補足説明・小本文 | **12pt** |
| 図の軸ラベル・条件テキスト | **12pt** |
| 参考文献・キャプション・注釈 | **12pt** |

> **目安**：迷ったら本文 20pt、タイトル 28pt を基準にする。
> **優先ルール**：スライド中の文字サイズは、**タイトル 28pt、本⽂ 20pt、本文の強調 24pt、参考文献・実験条件・出典などの補足情報 12pt** を原則とし、このルールを他の細かなサイズ指定より優先する。

- 強調したい数値・結果はテキスト色を変える（赤 or 青）

## 5. スライドタイプ別レイアウト

### ① タイトルスライド（全発表共通）

```
[発表タイトル ]（中央配置・大きめテキスト）

[日付・所属・発表者名]（サブタイトル領域）
```

**場面ごとの差異：**

| 場面 | タイトル部分 | サブタイトル部分 |
|------|-------------|----------------|
| 報告会 | `報告会 No.XX`（72pt）| 日付 + 研究室名 + 名前（32pt）|
| 学会発表（日本語） | 研究タイトル（28〜32pt・太字） | ○発表者名・共著者・所属（24pt）|
| 学会発表（英語） | 英文研究タイトル（28pt） | ○\<presenter name\>, \<co-authors\>, \<affiliation\>（英語）|
| 研究紹介 | `研究紹介`（28pt）| 研究室名・名前（24pt）|
| 修論発表 | 論文タイトル（32pt・太字） | 専攻・研究室・名前・発表日（24pt）|

### ② コンテンツスライド（標準レイアウト）

```
スライドタイトル（28pt）　　　　　　　　　　[スライド番号]

▸ セクション名（24pt）
  ・詳細説明や手順（20pt）
  ・詳細説明や手順（20pt）

▸ 別セクション名（24pt）
  ✓ 知見・結論（20pt）
  ✓ 知見・結論（20pt）
```

- スライド番号は**右上または右下の隅**に配置（全スライド）
- タイトルは上部、残りのスペースを図・テキストで分割

### ③ 実験手順・合成スライド（報告会で頻出）

```
反応名・操作名（28pt）

[反応条件テーブル：物質名・mmol・eq]

↓ 操作手順（20pt）
・手順1
・手順2
・TLC確認 → 結果

[写真・TLC画像]
```

- 試薬量はテーブル形式（物質名 | 量 | mmol | eq）
- 操作フローは`・`箇条書きで時系列に
- TLC結果は簡潔に記載（`TLC① (H:E=4:1)` など）

### ④ 今後の予定スライド（報告会の末尾）

```
今後の予定（28pt）

▸ テーマ① （24pt）
  ・具体的なタスク（20pt）
  ・具体的なタスク（20pt）

▸ テーマ② （24pt）
  ・具体的なタスク（20pt）
```

### ⑤ 結語スライド（学会発表・修論）

```
結語（28pt）

▸ まとめ
  ✓ 主要な結論1（20pt）
  ✓ 主要な結論2（20pt）

▸ 今後の展望
  ✓ 今後の課題1（20pt）
  ✓ 今後の課題2（20pt）
```

英語版（国際学会）：
```
Conclusion

▸ [Subheading]
  ✓ Finding 1
▸ Future outlook
  ✓ Task 1
```

### ⑥ 補助スライド（学会発表の末尾）

- `補助スライド`（または `Supporting Slides`）という**見出しスライドを1枚**挟む
- 以降に補足データ・詳細解析を配置

## 6. 発表場面ごとのスライド構成

### 報告会（定期進捗報告）：6〜15枚程度

1. タイトル（報告会 No.XX + 日付・所属）
2. 修士/博士テーマ概要（研究の背景・目的の再確認）
3. 実験・合成進捗①（試薬表＋操作手順＋TLC結果）
4. 実験・合成進捗②…（必要枚数）
5. 解析・シミュレーション進捗（あれば）
6. 今後の予定（▸ 複数セクション）

### 学会発表（国内・日本語）：20〜50枚程度

1. タイトル
2. 先行研究・背景
3. 研究目的と合成経路
4. 実験結果（CL、PXRD、TG-DTA 等）×複数枚
5. 速度論解析（モデルフィッティング）
6. 考察
7. シミュレーション
8. 結語（まとめ＋今後の展望）
9. 謝辞
10. 補助スライド＋補足データ

### 学会発表（国際・英語）：20〜25枚程度

- 日本語発表と同じ流れで全文英語化
- スライドサイズは全場面共通で 16:9


## 7. 測定条件の記載形式

測定条件はコンマ区切りで1行に凝縮する：

```
加熱温度:<温度>, <測定軸>:<範囲>, 測定時間:<時間>, 検出器:<装置型番>, <ビームライン or 装置設置場所>
```

英語版：
```
Heating to <temp>, <axis> = <range>, Measurement time: <time>, <detector model>, <beamline or facility>
```

実例（PXRD 等温測定の場合）:

```
加熱温度:120℃一定, 2θ/°:0~48, 測定時間:60分, 検出器:<detector model>, <beamline>
```

## 8. 図・グラフのルール

- 軸ラベル：**12pt**、凡例：**12pt**
- グラフのタイトルは基本省略（スライドタイトルで代替）
- 実験値とシミュレーション値は**同グラフに重ねてプロット**
- 凡例テキスト例：
  - `Experimental intensity` / `Simulation intensity`
  - `Experimental reacted rate` / `Simulation reacted rate`
- グラフ軸ラベルは英語でも可（日本語発表でも混在OK）

## 10. 化学・数式の表記

- 添字は正しくフォーマット（CO₂、S₀→S₁、k₁、k₂）
- 速度定数はイタリック体（*k*、*n*）
- ギリシャ文字はそのまま使用（Ф_CL、θ、α）
- 化学反応式：`A + A → B + A`（スペースあり、矢印は`→`）

## 11. 図表・ビジュアライゼーションのルール

**「テキストを減らし、図表で説明する」を基本方針とする。**

### 基本方針
- 各スライドに図表を 1 つ以上配置し、テキストは **3〜5 行以内** に抑える
- 数値の傾向・比較・手順は、テキストより図・グラフ・フローチャートで示す
- テキストは図では伝えきれない「解釈・結論」のみに絞る

### 原論文の図表の扱い
- **論文紹介・文献レビューのスライドでは、原論文中の図表を積極的に使う。**
- 特に、**結果の比較図・複数パネル図・模式図・実験 vs シミュレーション比較図**は、無理に描き直さず、原論文の図表を切り抜いて載せることを優先する
- 原図を使うときは、**必要部分だけをトリミング**して大きく見せ、不要な余白や本文部分は入れない
- 原図を載せたスライドには、**図番号つきで出典を明記**する（例：`Source: Gallant et al., Chem. Mater. 2025, Figure 4.`）
- ただし、**単純な表・比較ボックス・フローチャート・再現しやすい概念図**は、引き続き `python-pptx` の shapes / table / chart で再構成し、PowerPoint 上で編集可能にする
- 判断に迷ったら、**理解しやすさを優先して原図を使い、編集しやすさを優先して再構成するのは単純図だけ**に限定する

| 目的 | ライブラリ |
|------|-----------|
| グラフ・チャート全般 | `matplotlib` |
| フロー図・模式図 | `matplotlib.patches` |
| CA グリッド・行列の可視化 | `matplotlib` + `numpy` |
| 有機分子構造 | `RDKit` (`rdkit.Chem.Draw`) |
| データ集計・比較表 | `matplotlib` テーブル or `pandas` |

### 図の作成手順（Python スクリプト → PPTX 埋め込み）
1. `matplotlib` で図を生成して `figures/slide_fig_XX.png`（CWD 相対の `figures/` ディレクトリ）に保存（DPI=150〜200）
2. `python-pptx` の `slide.shapes.add_picture()` でスライドに埋め込む
3. 図のサイズは **スライド幅の 70〜90%** を目安に配置する

### matplotlib の日本語フォント設定（必須）
matplotlib のデフォルトフォント（DejaVu Sans）は日本語非対応。**必ずスクリプト冒頭で以下を設定すること：**

```python
import pptx_helpers as h
h.configure_matplotlib_japanese()  # 自動でクロスプラットフォーム検索 + 設定
```

内部的には `_find_msgothic_path()` が macOS の PowerPoint / Word バンドル、Windows の `C:\Windows\Fonts`、Linux のシステムフォントディレクトリを順に探索する。非標準パスにインストールしている場合は環境変数 `CAW_SLIDES_MSGOTHIC` でフルパスを指定できる。

手動設定が必要な場合の参考（非推奨、上記 helper で十分）:

```python
import matplotlib.font_manager as fm
import os
_FONT_PATH = os.environ.get("CAW_SLIDES_MSGOTHIC") or "<path/to/msgothic.ttc>"
fm.fontManager.addfont(_FONT_PATH)
_FONT_NAME = fm.FontProperties(fname=_FONT_PATH).get_name()  # 'MS Gothic'
plt.rcParams['font.family'] = _FONT_NAME
```

この設定なしに日本語を含む図を生成すると、文字が縦長の□（豆腐）になる。

### matplotlib で使える記号・使えない記号
MS Gothic は `✓`（U+2713）や `✗`（U+2717）をサポートしない → 縦長の□（豆腐）が表示される。

**代替記号を使うこと：**

| 意味 | 使えない | 代わりに使う |
|------|---------|------------|
| 正・良い | `✓` | `○` |
| 否・悪い | `✗` | `×` |
| 優秀 | — | `◎` |
| 注意 | — | `△` |

### 図のスタイル
- 背景色：白（`#FFFFFF`）
- フォント：MS Gothic（上記設定後）
- カラー：スライドのパレット（`#4472C4` 青・`#FF0000` 赤・`#00AC48` 緑）に合わせる
- 凡例・軸ラベルは必ず付ける（フォントサイズ 11〜13pt 相当）
- `plt.rcParams['axes.spines.top'] = False` 等でスッキリした見た目に

| 構成 | 使い分け |
|------|---------|
| 図 100%（テキストなし or 下部 1 行のみ） | 結果・比較スライド |
| 図 70% + テキスト 30%（左右分割） | 説明付き図スライド |
| 図 100%（フロー・模式図が全面） | ワークフロー・手順スライド |

## 12. スライドデザイン7原則（プロジェクター映え・視認性優先）

フィードバック（2026-04-03）を受けて制定。研究発表スライドを作るときは常にこの7原則を守る。

| # | 原則 | 具体的ルール |
|---|------|------------|
| 1 | **1スライド1メッセージ** | タイトル＋要点＋視覚要素（図・グラフ）で完結。情報を詰め込まない |
| 2 | **派手なアニメ・背景画像なし** | アニメーション禁止。プロジェクター映え優先 |
| 3 | **白背景** | スライド背景は常に白（`#FFFFFF`）。見やすさ最優先 |
| 4 | **強調は太字・色文字** | キーワードは **bold** ＋ 色（青 `#1A56A0` または赤 `#C0392B`）で強調 |
| 5 | **黒文字＋白背景でコントラスト** | 本文テキストは `#222222`（ほぼ黒）。淡色文字を使わない |
| 6 | **グリッド整列** | すべてのオブジェクトをグリッドに揃える。余白は左右 `0.4"` 以上 |
| 7 | **左上→右下の視線誘導** | タイトル（左上）→ 図（中央）→ キーメッセージ（下部）の順に配置 |

### フォントサイズ（スライドテキストボックス）

| 用途 | サイズ |
|------|--------|
| スライドタイトル | **28pt Bold** |
| 本文・キーメッセージ（最小） | **20pt** |
| 強調テキスト（そのスライドで最も伝えたい内容） | **24pt Bold＋色** |

> 補足情報（参考文献・実験条件・出典）のみ 12pt を許容し、それ以外は本文 20pt、強調 24pt を守る。

### 編集可能オブジェクトの優先順位

PowerPoint 上で編集できるよう、以下の優先順位でオブジェクトを選択する：

| コンテンツ種別 | 推奨手法 | 理由 |
|----------------|----------|------|
| データグラフ（折れ線・棒等） | **python-pptx LINE/BAR チャート** | PowerPoint 内でデータ編集可能 |
| 比較ボックス・フローチャート | **python-pptx shapes** (add_shape) | クリックして文字・色・位置を直接編集可能 |
| 比較表・まとめ表 | **python-pptx table** (add_table) | セル単位で編集可能 |
| 分子構造式 | **RDKit → PIL PNG → add_picture** | RDKit が PIL Image を直接出力（Cairo 不要） |
| 複雑なビジュアル（CA グリッド等） | **matplotlib PNG** | 形状が複雑で shapes では再現困難 |

> `svgwrite` → `cairosvg` → SVG 埋め込みは **Cairo ネイティブライブラリ**が必要。  
> macOS に Homebrew で cairo をインストール済みでない場合は上記の代替手法を使う。
>
> **補足**：原論文に高情報量の図表がある場合は、上の優先順位よりも**原図の切り抜き掲載を優先してよい**。特に複雑な比較図・多面図・実験結果図は、再作図より原図掲載のほうが正確で伝わりやすい。

### テキストボックス・レイアウト検証ルール

今回のフィードバックを受けて追加。**「見た目上置けている」ではなく、「PowerPoint を開いたときに崩れず読める」ことを合格条件にする。**

- **本文を枠で囲う場合は、必ずテキストが枠内に収まるようにする。**
- `python-pptx` で本文ボックスを作るときは、原則として **word wrap を有効化し、`TEXT_TO_FIT_SHAPE` 相当の自動縮小を入れる**。理由：生成時に収まって見えても、PowerPoint 側のレンダリング差であふれることがあるため。
- ただし、**自動縮小に頼りすぎて極端に小さい文字にしない**。本文が 16pt 未満まで落ちそうなら、文字を減らすか、ボックスを広げるか、スライドを分割する。
- **枠つき本文ボックスの高さは「入れたい文章量」ではなく「実際に入る文章量」で決める。** 特に 24pt 見出し + 20pt 本文を複数行入れる場合、見出しぶんの高さを別で見積もる。
- **複数の図・テキストブロックを並べるときは、座標上の隙間を最低でも 0.12" 程度確保する。** 理由：画像の実アスペクト比調整や PowerPoint 内の文字再流し込みで、見かけ上重なりやすいため。
- **図同士・図とテキスト・テキスト同士は絶対に重ねない。** 意図的な重ね合わせ表現でない限り、重なりはレイアウト失敗として扱う。
- **背景用の大箱をそのまま本文テキスト領域として使わない。** 図・模式図・カードを同じ箱の中に置く場合は、見出し・本文・図の領域を別オブジェクトで明示的に分ける。理由：PowerPoint 側の文字再配置で、背景箱のテキストが図にかぶりやすいため。
- `add_picture_fit()` のようなアスペクト比維持配置を使う場合、**見込みサイズではなく最終描画サイズで周囲との干渉を考える**。縦長画像は想定より横幅が細くなり、横長画像は想定より高さが低くなるので、左右・上下の余白を先に固定する。
- **表の上に見出しを重ねない。** 付録や一覧スライドでは、見出しは表内テキストとして入れるより、独立したラベルボックスとして配置する。
- 1枚に図を3つ以上置く場合は、**先に図の占有領域を決め、残った領域に本文を書く**。本文を書いた後に図を押し込まない。
- **長い解説は右側の大箱1つに詰め込まない。** 16:9 スライドで右カラムを使う場合、説明は 3〜5 行ごとの小ブロックに分けるか、スライドを増やす。
- **分子構造や模式図らしく見せる図は、幾何が意味を持つ形で描く。** 原子と結合の位置関係が曖昧になるなら、無理に pseudo-structure を描かず、RDKit 画像かラベル付きの単純模式図に切り替える。理由：見た目だけ分子らしい図は、かえって内容を誤解させるため。

### 生成後の確認手順

- PowerPoint 生成後は、**少なくとも全スライドについて「文字の枠内収まり」「図やボックスの重なり」「下部のキーバーと出典の非干渉」を確認する**。
- `python-pptx` の XML 上で `normAutofit` などが入っているだけでは不十分で、**最終的な配置座標とサイズも確認する**。
- 崩れやすいのは次のパターン：
  - 右カラムに長文をまとめたスライド
  - 図を上段2枚、本文を下段1箱にしたスライド
  - 下部のキーメッセージ帯と注釈・出典を近接させたスライド
  - 表の上に別の見出しや枠を重ねたスライド
- 1回目の生成で少しでも窮屈に見えたら、**「この程度なら入るだろう」と判断せず、先にボックスを広げるか文章を分ける**。

## 14. 実装パターン（pptx_helpers 利用、canonical ガイド）

**2026-04 に確立**。本セクションは `pptx_helpers.py` の使い方と強調 tier の運用規約を集約したもの。新規スライド作成時はここを優先参照する。

### 14-1. 物理レイアウト（16:9 / 13.33" × 7.5"）

コンテンツスライドは 3 層構造に統一：

| y 座標 (inch) | 要素 | helper |
|-------------:|------|--------|
| 0.12 – 0.82 | Title + Slide number + 青の separator bar | `add_slide_chrome(slide, title, slide_number)` |
| 1.18 – 6.13 | 本文ゾーン（body card / chart / table / flow diagram） | 各種 `add_*` helper |
| 6.28 – 6.86 | Key-message band（**L1 強調**: pale blue fill + 黒枠 + shadow） | `add_key_message_band` or `loud_key_message` |

表紙スライドは例外：category pill / 大見出し / hero chart or figure / focus pill (L1)。

> 出典・引用が必要なスライド（特に論文紹介）では、本文ゾーン内に出典文を置くか、必要なら `add_source_line` ヘルパを呼んで本文の末尾に小さく添える。出典をすべてのスライドに置くルールは廃止（読み手の認知負荷削減のため）。

### 14-2. 強調の 3 tier（L1 / L2 / L4。L3 は廃止）

| Level | shadow | border | fill | 使用場面 |
|-------|:------:|:------:|:----:|---------|
| **L1 LOUD** | ✓ | ✓ | ✓ | 各スライドで **一番伝えたい 1 要素**。通常は key-message band、表紙のみ focus pill |
| **L2 STRONG** | ✗ | ✓ | ✗ | 枠線だけで目を引きたい透明箱。稀 |
| **L4 QUIET** | ✗ | ✗ | ✗ | 本文・callout など装飾なしで置くテキスト |

#### 鉄則

1. **L1 は 1 スライド 1 個。** 複数置きたくなったら 1 つに絞る
2. **同列に並ぶ要素は必ず同じ tier。** 4 つの pill が並ぶ場合、1 個だけ L1 にせず全部 L4 にして、強調したい 1 個だけ font size / color で差を付ける
3. **L1 の中身はそのスライドで一番伝えたい内容**を書く（「まとめ」のような汎用語ではなく具体的な主張）

### 14-3. フォントサイズ・色で強調を足す

| 用途 | サイズ | 色 |

- **PNG 埋込は禁止**。`add_chart` でネイティブ作成（ユーザーがダブルクリックで埋込 Excel を編集可）

- **補助線** = デフォルト OFF。必要時のみ薄いグレー `#DDDDDD` 0.5pt

Helper:
- `add_scatter_line_chart(slide, series_data=[(name, xs, ys), ...], title=, x_label=, y_label=, gridlines=False)`
- `add_bar_chart(slide, categories=[...], series_data=[(name, values), ...], title=, gridlines=False)`

### 14-5. フロー図・タイムライン図（ネイティブ矩形 + 矢印のみ）

- **PNG 禁止**。matplotlib で生成した figure を貼るのは NG
- 矩形: `add_flow_box(slide, text, ...)` が `MSO_SHAPE.ROUNDED_RECTANGLE` を追加
- 矢印: `add_flow_arrow(slide, ..., direction="right")` — **`MSO_CONNECTOR.STRAIGHT` ではなく `MSO_SHAPE.<DIR>_ARROW`**（connector は round-trip で壊れる事故あり）

座標 hygiene:
- **すべての座標は `int()` で coerce**（python-pptx の `/` float 混入で再読込エラー or 位置ズレ）
- 分割計算では `//`（整数除算）を使う

### 14-7. 生成後の自動検証（必ず通す）

1. `assert_no_overlap(rects)` を各スライドビルダー末尾で呼ぶ → 重なりがあれば `ValueError` で停止
2. python-pptx で再読込して shape 矩形の交差が **0 件** であることを確認
3. **L1 shape が各スライド 1 個だけ** であることを確認
4. **チャート数 ≤ 2 / スライド** を確認
5. （任意）`soffice --headless --convert-to png` で PNG レンダ目視

### 14-8. canonical 作成手順

1. 発表場面・枚数目安・言語・既存アセットを確認
2. `.company/presentation/notes/YYYY-MM-DD-plan.md` に構成計画（スライドタイトル / 各スライドの L1 メッセージ）を書く
3. `.company/presentation/scripts/generate_<purpose>_<YYYYMMDD>.py` を作成し、`pptx_helpers` から必要な helper を import
4. 本セクションの 14-1 〜 14-5 に沿って各スライドビルダーを書く：
   - `add_slide_chrome` → 本文ゾーン → `loud_key_message`（出典が必要なら本文ゾーン内 or 末尾に `add_source_line`）
   - 全座標を `int()` で coerce、`//` で整数除算
   - 本文カードは装飾なし（デフォルト）、`text_summary` で値 callout、pill は L1 に限定
5. `assert_no_overlap` が末尾で必ず走ることを確認
6. 生成 → python-pptx で再読込して 14-7 の検証を全項目パス
7. PowerPoint で実際に開いて目視確認（LibreOffice があれば PNG レンダリング）
