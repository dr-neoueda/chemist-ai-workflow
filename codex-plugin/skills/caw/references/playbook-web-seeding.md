# Playbook の web 種まき（初回利用時・1 ツールだけ・遅延）

ユーザーがある計算ツールを**初めて使うとき**（`caw-input` の cold-start 検出、または「◯◯の Playbook を web から種まきして」の明示要求）に、**そのツール 1 つだけ**、**信頼性の高いソースから初期 Playbook を種まき**する手順。空 Playbook のコールドスタート（使い始めは中身が無く価値が出ない）を、その場の web 検索で埋める。配布物には汎用コンテンツを同梱しない（per-technique スキル量産の失敗を繰り返さない）ための live 生成方式。

> **オンボーディングでは自動種まきしない**（名指しツール数だけ web 検索エージェントを並列起動すると初期構築でトークンを大量消費し、caw を使い始める前に利用枠を使い切るため）。同梱の starter playbook（`references/playbook-starters.md` 由来）でそのまま使い始められ、種まきは「実際にそのツールを使う時」まで遅延する。

## いつ・どう走らせるか

- **タイミング**：**そのツールを初めて使うとき**。`caw-input` が対象ツールの Playbook を読み、`## Lessons Learned` も `## 外部リファレンス（web 由来・要検証）` も空の **cold-start** なら、種まきするか **1 回だけ尋ねる**（任意・既定は「今は入力を進める」）。ユーザーの「◯◯を web から種まきして」の明示要求でも走る。**オンボーディングでは走らせない**。
- **粒度**：**1 回につき 1 ツールだけ**。onboarding で複数ツールを並列起動しない（トークン枠の保護が目的）。1 ツールの種まきは 1 パスで完結させ、**web 検索は最小限**（一次資料・公式を数クエリ）に抑える。
- **web 検索が使えない CLI / 環境**：skip し「後から `caw-playbook` で追記できます」と案内する。
- **完了報告**：終わったら 1 回だけ「&lt;tool&gt; の初期 Playbook を `## 外部リファレンス（web 由来・要検証）` に置きました（web 由来・要検証。実際に回した知見は Lessons Learned に書けば上書きされます）」と通知する。

## 各エージェントへの入力

- 対象ツール名 1 つ（例：Gaussian / ORCA / CP2K / GROMACS / MACE・MLIP / VASP / Quantum ESPRESSO 等）
- ユーザーの**研究分野**（Call 1 大分類・Call 2 中分類）と対象系 ── 汎用チュートリアルでなく、その分野で使う既定に寄せるため

## 各エージェントの成果物（何を書くか）

対象ツールの `office/computation/playbooks/<tool>.md` に、次の 1 セクションを**追記**する（既存 `## Lessons Learned` には一切触れない）：

```
## 外部リファレンス（web 由来・要検証）
> ⚠️ 以下は web 由来の一般的な出発点であり **未検証**。一次資料と自分の run で確認してから既定化すること。
> 実際に回して得た知見は `## Lessons Learned` に書き、**そちらが本セクションより常に優先**される。
> 最終更新: YYYY-MM-DD（種まき時）

### 推奨される出発点（意思決定に使える既定）
- <ツールに応じた既定>（出典 URL）

### よくある罠・version 依存の文法
- <落とし穴／バージョン差>（出典 URL）
```

**「意思決定に使える既定」の中身**（ツール種別に応じて選ぶ。チュートリアルの丸写しにしない）：
- 量子化学（Gaussian/ORCA/Psi4）：目的別の**汎関数・基底**の定番、収束/安定性フラグ、TS/IRC の定石、既知の構文の罠
- 古典 MD（GROMACS/AMBER/LAMMPS/OpenMM）：**力場**選択、thermostat/barostat、`dt`・cutoff・PME、平衡化手順
- 周期系 DFT（CP2K/VASP/QE）：**汎関数・擬ポテンシャル/basis set**、k 点・cutoff、SCF/smearing、格子最適化の注意
- MLIP/MLFF（MACE 等）：foundation model の選択、fine-tune の主要ハイパー、committee/AL の目安、NPT に必要な stress の有無

## 規律（厳守）

- **一次資料・公式を優先**：ベンダーマニュアル／公式 docs／被引用の多い手法論文。**公式は単一ソース可、非公式は 2 つ以上で裏取り**（[[feedback_official_single_nonofficial_multi_source]]）。
- **各記述に出典 URL を必ず添える**。二次情報は出典併記し、機械的に正典化しない。
- **計算入力の構文が絡む種は、特にベンダー一次資料（公式マニュアル）で裏取り**してから記す（[[feedback_comp_input_template_primary_source]]：`! CASSCF` 欠落で HF が黙って走る等、generic ソースも LLM も普通に間違える）。
- **数値をでっち上げない**：信頼できる出典が見つからない項目は「未取得（要一次資料）」と書いて空欄化する。憶測で埋めない。

## 非目標

- `## Lessons Learned` を書き換えない（ユーザー本人が run から得た検証済み知見に予約）。web 種まきは別セクションに隔離する。
- チュートリアル／長い散文を書かない。**既定・罠・出典**に絞る。
- 配布物（このリポジトリ）に汎用 Playbook を同梱しない。種まきは各ユーザーのプロジェクト内で live 生成する。

## 既存の `_past-data` seeding との関係

- `_past-data`（ユーザーの過去 run）→ `## Lessons Learned` に seed＝**本人の・検証済み**。
- web 種まき → `## 外部リファレンス（web 由来・要検証）` に seed＝**一般的・未検証**。
- 両者が食い違うときは **`## Lessons Learned`（本人の実測）が優先**（caw-input の「後発 Lessons 優先」と同じ原則）。

## 反復・追加ツール

同じ手順は、ユーザーが後からツールを足したときにも**そのツール 1 つだけ**単発で走らせてよい（本ファイルを読んで 1 パス）。**常に 1 ツール単位**・オンボーディングでの一括自動起動はしない。
