# Playbook の web 種まき（オンボーディング後・バックグラウンド）

オンボーディングの Call 4 でユーザーが名指しした計算ツール／アプリについて、**信頼性の高いソースから初期 Playbook を種まき**する手順。空 Playbook のコールドスタート（使い始めは中身が無く価値が出ない）を、**そのユーザーの named ツールだけ・その場の web 検索**で埋める。配布物には汎用コンテンツを同梱しない（per-technique スキル量産の失敗を繰り返さない）ための、live 生成方式。

## いつ・どう走らせるか

- **タイミング**：scaffold 完了後（完了メッセージ表示後）に**バックグラウンドで自動起動**。オンボーディングの funnel は一切止めない（ユーザーを待たせない）。
- **粒度**：**1 ツール＝1 エージェント**。ユーザーが複数ツールを挙げたら**並列**で走らせる（並列サブエージェントが使える CLI＝並列、無い CLI＝順次にフォールバック）。web 検索が使えない CLI では skip し、「後から `caw-playbook` で追記できます」と案内する。
- **完了報告**：全エージェント完了後に 1 回だけ「N ツールの初期 Playbook を各 `## 外部リファレンス（web 由来・要検証）` に置きました」と通知（進捗の逐次報告はしない）。

## 各エージェントへの入力

- 対象ツール名 1 つ（例：Gaussian / ORCA / CP2K / GROMACS / MACE・MLIP / VASP / Quantum ESPRESSO 等）
- ユーザーの**研究分野**（Call 1 大分類・Call 2 中分類）と対象系 ── 汎用チュートリアルでなく、その分野で使う既定に寄せるため

## 各エージェントの成果物（何を書くか）

対象ツールの `office/computation/playbooks/<tool>.md` に、次の 1 セクションを**追記**する（既存 `## Lessons Learned` には一切触れない）：

```
## 外部リファレンス（web 由来・要検証）
> ⚠️ 以下は web 由来の一般的な出発点であり **未検証**。一次資料と自分の run で確認してから既定化すること。
> 実際に回して得た知見は `## Lessons Learned` に書き、**そちらが本セクションより常に優先**される。
> 最終更新: YYYY-MM-DD（種まき時）

### 推奨される出発点（意思決定に使える既定）
- <ツールに応じた既定>（出典 URL）

### よくある罠・version 依存の文法
- <落とし穴／バージョン差>（出典 URL）
```

**「意思決定に使える既定」の中身**（ツール種別に応じて選ぶ。チュートリアルの丸写しにしない）：
- 量子化学（Gaussian/ORCA/Psi4）：目的別の**汎関数・基底**の定番、収束/安定性フラグ、TS/IRC の定石、既知の構文の罠
- 古典 MD（GROMACS/AMBER/LAMMPS/OpenMM）：**力場**選択、thermostat/barostat、`dt`・cutoff・PME、平衡化手順
- 周期系 DFT（CP2K/VASP/QE）：**汎関数・擬ポテンシャル/basis set**、k 点・cutoff、SCF/smearing、格子最適化の注意
- MLIP/MLFF（MACE 等）：foundation model の選択、fine-tune の主要ハイパー、committee/AL の目安、NPT に必要な stress の有無

## 規律（厳守）

- **一次資料・公式を優先**：ベンダーマニュアル／公式 docs／被引用の多い手法論文。**公式は単一ソース可、非公式は 2 つ以上で裏取り**（[[feedback_official_single_nonofficial_multi_source]]）。
- **各記述に出典 URL を必ず添える**。二次情報は出典併記し、機械的に正典化しない。
- **計算入力の構文が絡む種は Codex で二段クロスチェック**してから記す（[[feedback_comp_input_template_primary_source]]：`! CASSCF` 欠落で HF が黙って走る等、generic ソースも LLM も普通に間違える）。
- **数値をでっち上げない**：信頼できる出典が見つからない項目は「未取得（要一次資料）」と書いて空欄化する。憶測で埋めない。

## 非目標

- `## Lessons Learned` を書き換えない（ユーザー本人が run から得た検証済み知見に予約）。web 種まきは別セクションに隔離する。
- チュートリアル／長い散文を書かない。**既定・罠・出典**に絞る。
- 配布物（このリポジトリ）に汎用 Playbook を同梱しない。種まきは各ユーザーのプロジェクト内で live 生成する。

## 既存の `_past-data` seeding との関係

- `_past-data`（ユーザーの過去 run）→ `## Lessons Learned` に seed＝**本人の・検証済み**。
- web 種まき → `## 外部リファレンス（web 由来・要検証）` に seed＝**一般的・未検証**。
- 両者が食い違うときは **`## Lessons Learned`（本人の実測）が優先**（caw-input の「後発 Lessons 優先」と同じ原則）。

## 後日の再利用（door は開けておく）

住処はオンボーディング専用ステップだが、ユーザーが後からツールを 1 個足したとき、**同じ手順をそのツール 1 つだけに対して単発で再実行**してよい（本ファイルを読んで 1 エージェント走らせる）。オンボーディング時に自動配線はしない。
