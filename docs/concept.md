# コンセプト・設計方針

## 商品名（暫定）
- **「Chemist's AI Workflow」**（仮）
- 副題候補：「化学研究を 9 部署に分ける — AI エージェント実践ハンドブック」

## 一行ピッチ

> 化学者が、実験・論文・計算・申請書・発表資料を **9 つの "AI 部署"** に分けて回す——
> ChatGPT を超えた、研究プロセス全体の AI 化メソッド。

## 中核アイデア

ChatGPT を「賢いチャット相手」として使うレベルから、**研究室そのものを AI エージェントで多部署化する**レベルへ。

- 秘書（Secretary）—— 窓口・TODO・壁打ち
- 文献部（Research / Papers）—— 文献検索・要約・DB 化
- 計算管理部（Computation）—— Gaussian/GROMACS ジョブ管理
- 実験部（Experiment）—— 実験の段取り・電子ノート・試薬/サンプル在庫・安全
- データ解析部（Analysis）—— 解析スクリプト・可視化（手法非依存の解析コンパニオン）
- 開発部（Engineering）—— Python ツール・ユーティリティ
- 論文執筆部（Writing）—— LaTeX 原稿・図表・参考文献
- レビュー部（Review）—— コード品質・計算妥当性
- プレゼン部（Presentation）—— 発表資料・スライド生成

→ **ファイルシステム上に "部署フォルダ" を作り、各部署が自分のルール（CLAUDE.md / AGENTS.md など）に従って働く。**

## CLI 中立性の原則

| ✅ 中立に書く | ❌ 特定 CLI に依存させない |
|--------------|--------------------------|
| 部署のフォルダ構造 | 特定スラッシュコマンド名のみで運用すること前提 |
| 運用ルール（同日 1 ファイル、追記専用、kebab-case） | 特定 Hook 実装に依存した自動化 |
| TODO 形式・ノート形式 | 特定プラグイン（cc-company / ECC）の前提 |
| 部署間連携の書き方 | 特定 MCP サーバー必須の機能 |

教材内では：
- **核（core/）** で「考え方」「ファイル構造」「ルール」を CLI 非依存で説明
- **実装 A〜C** で各 CLI への落とし込みを並列に提示

## 差別化ポイント

1. **化学者特化の事例**：Gaussian/GROMACS、IR/NMR/XRD 解析、結晶相反応、論文執筆を実例で扱う
2. **実働システム由来**：作者自身が 2026 年から日常運用している `office/` 9 部署の実物を再現可能テンプレートとして提供
3. **ベンダーロックインを避ける設計**：Anthropic でも OpenAI でも Google でも回せる
4. **品質管理が組み込み**：Claude + Codex の二段レビュー、TDD、search-first などの実運用ノウハウを含む

## 競合・隣接商品

- **Anthropic 公式 docs / Claude Code skills repo**：無料・汎用。差別化＝化学特化＋方法論統合
- **note / Zenn の "Claude Code 活用法" 記事群**：単発 Tips が多い。差別化＝体系化された方法論
- **Andrej Karpathy 等の海外 AI tutorial**：英語・ソフトウェアエンジニア向け。差別化＝日本語・実験系研究者向け
- **ChemBERTa / DeepChem 等の AI for Chemistry**：モデル/ライブラリそのもの（研究内容の AI 化の素材）。caw は研究の**進め方**を多部署エージェントで回す **業務プロセスの AI 化** が重心。必要ならそうしたモデルの訓練・利用も同じ枠組みで支援する——道具の提供でなく**ワークフローの AI 化**が差別化

## スコープ — やれることに制限を設けない（化学者向けという identity だけ維持）

caw は **「ユーザーの研究が必要とすることなら何でも支援する／特定タスクを事前に拒否しない」** 方針で設計する。
ユーザーが持ち込んだデータ・課題に対し、**汎用ツール（pandas / numpy / scipy / RDKit・各種計算エンジン・MLIP 等）＋ユーザーごとに育つ playbook** で都度こなす。MLIP の訓練・fine-tune、モデルの評価、ちょっとしたツール作成なども、必要なら同じ枠組みで扱う（capability の制限は設けない）。

ただし **2 つだけ一定に保つ**：

1. **identity（正体・売り）= 化学者向けの研究ワークフロー支援**。汎用開発ツールには広げない（差別化＝買う理由を保つ）。形態はエージェント／CLI プラグイン。
2. **作り方の規律 = 抽象フレームワーク**。測定手法・解析ごとの具体スキルを量産せず、薄い土台＋汎用ツール＋育つ playbook で柔軟に対応する（過剰な作り込み・保守爆発を避ける）。詳細は [`analysis-companion-design.md`](./analysis-companion-design.md)。

> 「制限なし」は **ユーザーが頼めること** の話であり、**事前に作り込む専用機能を増やす** という意味ではない。抽象フレームワークゆえに、専用機能を出荷せずとも何でも手伝える。

### 役割境界（正直に・「全分野対応」とは謳わない）

化学全 16 領域のカバレッジ監査（2026-07-01）の結論は「**全分野で組織運営と下流解析は回るが、各分野を定義する
一次データ還元（ベンダーバイナリ取込・専用ソフト依存）は caw の外**」。caw が担うのは **①9 部署の組織運営 ②raw→数値化
後の下流定量解析＋規律 ③執筆・文献・playbook** の 3 つで、**ベンダー GUI/MATLAB 専用ソフトでの対話的 raw 還元
（SCXRD 精密化・XPS 定量・EPR シミュ・cryo-EM 再構成 等）は代替せず外部連携に委ねる**。詳細と領域別の期待値は
[`chemistry-coverage-audit.md`](./chemistry-coverage-audit.md)。横断ギャップは手法別スキルを増やさず 3 つの汎用資産
（取込アダプタ規約・外部ソフト orchestration 契約・高リスク解析チェックリスト）＋ caw-input のエンジン方言分離で対処する。
