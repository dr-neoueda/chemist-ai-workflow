## なぜ凍結したか

**実地検証で、Gemini CLI の無料枠では caw のオンボーディングすら完走できないと判明したため**
（第 1 回テストユーザー会・2026-06-19）。API キーが必須で、無料枠の割り当てが少なく、
ユーザーが caw を使い始める前に枠を使い切る。実用には有料 API が前提になる。

加えて、**商品モデルが「導入伴走」に変わった**（2026-08-21）ことで、伴走で相手の環境に入れるのは
**Codex CLI（本命）／ Claude Code（次点）／ Copilot CLI（企業向け）** の 3 系統になり、
Gemini 版を勧める場面が無くなった。

## 保守コストの実測（凍結を決めた根拠）

| | 行数 | コミット | 版上げ |
|---|---|---|---|
| gemini-plugin | **226** | 43 | 44 |
| plugin（本体） | 21,061 | 89 | 87 |

**226 行しかないのに、本体の変更のおよそ 2 回に 1 回は追従が要っていた。**
コードが小さいから安いのではなく、本体を変えるたびに発生する定額コストだった。

## 凍結中のルール

- **本体（plugin / codex / copilot）の変更を Gemini に追従させない**
- **版を上げない**（`gemini-extension.json` は 1.49.0 で据え置き）
- README と `GEMINI.md` に「非推奨・追従しない」と明記する
- `check-consistency.sh` が毎回「本体から何バージョン遅れているか」を表示する
  ── ずれは**隠さず、測れる形で見せる**

## 凍結を解除する条件

以下のいずれかが満たされたとき、解除を検討する：

1. Gemini CLI の無料枠が、caw のオンボーディングを完走できる水準に改善された
2. 有料 API 前提でよい顧客（Google 環境の組織）に対して、実際に伴走の引き合いがあった

解除する場合は、**凍結中に本体で起きた変更を全て洗い出して追従させる**必要がある。
遅れが大きいほどこの作業は重くなるので、`check-consistency.sh` の表示を定期的に見ること。
