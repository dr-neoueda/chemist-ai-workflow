# caw-analyze — 解析コンパニオン（研究トラック）

## いつ使うか

- `/caw-analyze` を実行したとき
- 「このデータを解析して」「測定結果をまとめて」「fit して」「この実験/計算の出力を定量して」「図にして」など、**データ＋知りたいこと**を持ち込まれたとき

`office/analysis/`（データ解析部）が無ければ `/caw` で追加するよう促す。**就活トラック**（`office/CLAUDE.md` 冒頭が `> トラック: 就活`）では「これは研究向けのスキルです」と伝える。

## 設計思想（重要）

caw-analyze は **「何を解析するか」を固定しない**。手法別スキルや固定パーサは持たず、**汎用ツールでその場に解析を組む“司会者”**として働く。価値は「規律 × ユーザーごとに育つ playbook」にある。設計の全体像は `docs/analysis-companion-design.md`。

- **手法非依存**：XRD でも CV でも速度論でも XAS でも、必要な解析を汎用ツール（pandas/numpy/scipy/matplotlib/RDKit/ASE 等）でその場に書く。
- **pre-baked パイプラインを持たない**：固定の技術別スキルは出荷しない。
- **使うほど特化**：繰り返す解析は **ユーザーの playbook** にレシピとして残し、次回からそこを起点にする（[`caw-playbook`](../caw-playbook/SKILL.md) を解析にも一般化）。

## はじめてモードを尊重する

`office/CLAUDE.md`（Codex/Copilot は `AGENTS.md`、Gemini は `GEMINI.md`）冒頭に `> 運用モード: はじめて` があれば、`caw` skill の「はじめてモードの挙動」を全応答に適用する：**平易な日本語**、専門用語は初出 1 行説明、各ステップ末に「次はこれをしましょう」を 1 つだけ。

## ワークフロー

### Step 0: プロファイルと既存レシピを読む
`work/profile/`（研究分野・活動・使用計算ツール・対象系）と、あれば `work/analyses/_playbook/`（このユーザーの解析レシピ）を読み、ユーザーの文脈に合わせる。**既存レシピがあればそれを起点**にする（毎回ゼロから組まない）。

### Step 1: データと問いを確定（必要なら per-data で聞く）
- 何のデータか・**単位**・形式・どこにあるか、そして **何を知りたいか**（定量？ fit？ 比較？ 可視化？）を確定する。
- **実験データは特色が強い**ので、ここで具体を尋ねる（測定手法・装置・列の意味・前処理の有無）。onboarding では聞いていない前提で、必要な具体をこの場で確認する。

### Step 2: データを整理（既存規約に沿う）
生データは `~/lab` の実験データ規約や `work/analyses/<topic>/` に沿って配置（ユーザーの既存構造を尊重し、勝手に作り替えない）。

### Step 3: 汎用ツールでその場の解析を組む
目的に合うライブラリ（pandas/numpy/scipy/matplotlib・必要なら RDKit/ASE/lmfit 等）で、**ユーザーの問いに合わせた解析スクリプト**を書く。固定パイプラインに当てはめない。スクリプトは `work/scripts/` か `work/analyses/<topic>/` に、再利用するなら残す。

### Step 4: 規律ガードレール（必ず効かせる）
- **物理量は単位明示**（コメントで `# kJ/mol`, `# Å`, `# eV` 等）。
- **再現性**：乱数 seed 固定・パラメータはハードコードせず引数/設定に・使った値を出力に記録。
- **境界で検証**：入力の NaN/欠損/単調性/単位を確認してから処理（信頼しない）。
- **正直な報告**：fit は R²・残差・前提を必ず添える。不確かさ・外挿・仮定を隠さない。
- **科学判断はユーザー**：手法選定・解釈はユーザーが決める。caw は規律ある協働者に徹する。

### Step 5: 残す価値があれば playbook に蒸留＋レビュー
- 繰り返す解析は、手順・使った汎用ツール・罠・検証観点を **ユーザーの解析 playbook**（`work/analyses/_playbook/<topic>.md`）に追記する（[`caw-playbook`](../caw-playbook/SKILL.md) 方式）。次回からそこが起点。
- **配布物でなくユーザーのローカル解析コード**でも、再利用する重要なものは Claude + Codex の二段レビューを案内（品質規律）。使い捨ての一回限り解析は不要。

## 制約・規律（厳守）

- **手法別の固定スキル/パーサを作らない**。汎用ツール＋playbook で都度こなす。
- **スターター素材を同梱しない**：レシピ playbook は空で始まり、ユーザーの実作業で育つ。
- **単位・再現性・境界検証・正直な報告**を毎回効かせる。
- **科学判断を肩代わりしない**（手法選定・解釈はユーザー）。

## CLI 中立

caw-analyze は方法論スキル（重い helper を同梱しない）。Claude Code / Codex CLI / Gemini CLI / GitHub Copilot CLI のどれでも、汎用ツールを `python3` 等で呼んで解析する。in（ユーザーのデータ＋問い）→ out（解析結果・図・playbook レシピ）に徹する。
