# caw-events — 企業の就活イベント深掘り＆今年度予測

就活モードのイベント収集スキル。**既定では 1 社を対象に**、その企業の就活イベント（インターン・説明会・座談会・選考イベント）と締切を**詳細に深掘り**し、**過去の開催実績から今年度の開催を予測**してカタログ化する。`caw-research`（個社の事業・選考研究）の隣に立つ「その企業のイベント担当」。**複数企業を横断して集めたい場合は、ユーザーがその旨を明示指示したときだけ**横断モードに切り替える。

## いつ使うか

- `/caw-events` を実行したとき
- 「<企業> のインターン情報を集めて」「<企業> の説明会・選考イベントをまとめて」「<企業> の就活イベントを深掘りして」「<企業> は今年いつ何のイベントをやりそう？」と言われたとき
- `caw-research` で個社研究した後に「この会社のイベント・締切も詳しく」と言われたとき
- **複数社・業界横断**で集めたいときは、ユーザーが「○○業界の主要各社で」「A 社・B 社・C 社をまとめて」のように**明示指示**したときのみ（→ 末尾「横断モード」）

`office/`（就活モード）が無ければ `/caw` で就活トラックのセットアップを促す。企業・業界研究部 / 秘書部が未作成なら作成を提案する。

## はじめてモードを尊重する

このスキルを実行する前に `office/CLAUDE.md`（Codex CLI / GitHub Copilot CLI では `AGENTS.md`）を読み、冒頭に `> 運用モード: はじめて` があれば、`caw` skill の「はじめてモードの挙動」を全応答に適用する：**平易な日本語**で話し、専門用語（インターン・オープンカンパニー・早期選考・本選考直結 等）は初出で 1 行説明を添え、各ステップの最後に**「次はこれをしましょう」を 1 つ**だけ提示する。

## ワークフロー（既定＝1 社深掘り）

### Step 1: 対象企業とシーズンを確認（不足は `AskUserQuestion`）

- **対象企業**：**1 社**（既定）。`work/companies/<企業>.md`（`caw-research` の出力）があれば読んで前提（事業・選考フロー・自分との接点）に使う
- **集めるイベント種別**：インターン／オープンカンパニー・1day／説明会・セミナー／座談会・OB/OG 訪問会／本選考（既定: **すべて**）
- **対象シーズン**：例「27 卒・2026 年度」（年度で変わるため必須）
- 任意：職種（事務系／技術系／DS 等）・地域
- **複数社・業界の指示が無ければ 1 社で進める**。明示があれば末尾「横断モード」へ

### Step 2: 情報源の特定（公式最優先＋就活サイト積極併用）

対象企業について、次を洗い出す：

- **① 公式（一次情報・最優先）**：新卒採用サイト・採用ページのイベント一覧・マイページ告知・キャリアページ・プレスリリース
- **② 就活サイト（積極的に併用）**：マイナビ／リクナビ／ワンキャリア／外資就活ドットコム／unistyle／Wantedly／逆求人（OfferBox 等）／口コミ（みん就／OpenWork 等）。**今年度の公式告知がまだ薄くても、就活サイト側の募集・体験記から積極的に拾う**
- 公式と就活サイトで食い違う場合は**公式を優先**し、就活サイト由来は**出典・取得日を明記**

### Step 3: 今年度イベントの詳細収集（深掘り）

確定／募集中の各イベントについて、取れた範囲で詳細を集める（取れない項目は空欄／「要確認」）：

| 項目 | 例 |
|---|---|
| 種別 | インターン / オープンカンパニー / 説明会 / 座談会 / 本選考 |
| 名称・テーマ | 「データサイエンス WS」「事業立案体感ワーク」 |
| 職種・コース | 事務系 / 技術系 / データサイエンス / 電気 |
| 形式・日数・場所 | 対面 / オンライン、1day / 2 日 / 5 日、本社 / 各拠点 |
| 対象 | 学年・専攻・卒業年度（例: 27 卒・院/学部） |
| 応募締切・実施日 | `2026-06-26` 締切 / 実施 `8/6-7` |
| 優遇・早期選考 | 早期選考あり / 本選考直結 / 優遇ルート |
| 報酬・交通費 | 日当 / 交通費 / 宿泊の有無 |
| 選考 | ES / 適性検査 / 面接 / 抽選 / 先着 |
| 口コミ・倍率 | 参加者の声・倍率（**非公式は複数ソースで裏取り**・出典必須） |
| 出典・取得日・状態 | URL・`2026-06-13`・公表済 / 要確認 / 未公表 |

- **ログイン必須・未公表で取れない情報は捏造しない**。「要確認」に分離し、確認導線（公式採用ページ URL）を残す
- 締切は流動的 → **取得日を必ず併記**し「最新は公式で確認」を明示
- **口コミ・倍率・選考難易度などの非公式情報は 2 ソース以上で裏取り**（公式は単一可）。出典が割れたら幅・年度を併記

### Step 4: 過去実績の収集と今年度の予測（★この企業を深く知る肝）

**この企業の過去 2〜3 年の就活イベント実績**を集め、**今年度の開催を予測**する：

1. **過去実績の収集**：就活サイトの体験記・過去の募集アーカイブ・公式の過年度告知から、例年のイベント（種別・時期・締切・コース・形式・優遇）を**年度ごとに整理**する
2. **パターン抽出**：例年の開催月・締切時期・コース構成の規則性を読む（例「DS WS は毎年 6 月下旬締切・8 月実施」「秋にキャリアセミナー」）
3. **今年度の予測**：まだ未発表のイベントについて、**「予測（昨年実績ベース）」**として想定時期・想定種別を提示する。**必ず予測ラベルを付け、根拠（過去の実日付）を併記**。確定情報と峻別し、断定・捏造しない
4. **表現例**：
   - 「サマーインターン（DS コース）：**昨年** 6/26 締切・8/6-7 実施 → **今年度は未発表（例年なら 6 月下旬締切・8 月上旬実施と予測）**」
   - 「秋オープンカンパニー：過去 2 年とも 10 月開催 → **今年度も 10 月頃と予測**」

### Step 5: カタログに構造化保存

`work/recruit/<企業slug>.md` に保存（**1 社 = 1 ファイル**）：

- **今年度の確定／募集中イベント**（1 イベント = 1 ブロック）
- **今年度の予測イベント**（「予測（昨年実績ベース）」セクションに分離して列挙）
- **過去実績**（年度別サマリ：いつ・何を・締切・コース）
- 冒頭に**カバレッジ**（取得イベント数・参照した情報源・取得日）＋締切が近い順サマリ
- **再実行時は差分更新**（新規告知・締切変更・募集終了を検知。**予測 → 確定への昇格**も反映）

### Step 6: HTML ビュー（実行時に `AskUserQuestion` で選択）

`work/recruit/<企業slug>.html`（既定は 3 ビュー同梱、要望に応じて個別）。**`caw-research` の HTML 可視化規約を踏襲**する：

- **① イベントカタログ**：その企業のイベントを**カード一覧**で表示。種別・職種・月で**フィルタ**。**確定／募集中／予測をバッジで区別**。各カードに締切・実施日・優遇/早期選考・出典・取得日
- **② 年間スケジュール・予測カレンダー**：その企業の年間タイムライン。確定イベントは実線、**過去実績ベースの予測は点線／淡色**で重ねる（締切が近いほど色を強める）。「昨年 → 今年度予測」が一目で分かるように
- **③ 過去 × 今年度 対照表**：行＝イベント種別／コース、列＝過去 2〜3 年の実績と**今年度（確定 or 予測）**。時期・締切・優遇の対比
- チャートは**オフライン自己完結（SVG）／ Chart.js** を選択。**見出しアンカー id と `<canvas id>` は別名**（`ch` 接頭辞）。各カード／行に**出典リンク＋取得日**、「要確認」「予測」は視覚的に区別

### Step 7: 秘書の選考スケジュールへ連携

- **確定**の締切・実施日（特に直近・志望度の高いもの）を `secretary/todos/YYYY-MM-DD.md` の選考スケジュールに**反映を提案**
- **予測**イベントも「例年なら○月頃」を**仮の節目**として登録提案（確定したら更新）。Notion 等を併用していれば秘書ルールの双方向同期に従う
- 締切が近い順に提示して**抜け漏れを防止**。差分（締切変更・締切間近・**予測 → 確定**）はアラート

## 横断モード（複数社・業界）— ユーザーの明示指示があるときだけ

ユーザーが「○○業界の主要各社で」「A・B・C 社をまとめて」のように**明示**したときだけ発動する。

- 対象社を確定（業界指定なら `work/companies/_industry/<業界>.md` や web 検索で主要企業を列挙 → ユーザーが追加／除外）。志望度・規模で**優先順位**を付け、対象社数 M を確定
- 各社に Step 2〜4（情報源特定・詳細収集・過去実績→今年度予測）を適用
- 保存は `work/recruit/<業界slug>.md`（**1 社 = 1 セクション**）。HTML の **③ は「企業 × イベント比較表」**（行＝企業、列＝優遇/早期選考/本選考直結/報酬/選考有無の有無マトリクス）に切り替え
- **カバレッジ（取得イベント数・N/M 社・未取得社一覧）を必ず報告**。無音の取りこぼし禁止

## 重要な注意事項

- **既定は 1 社深掘り**。複数社・業界横断はユーザーの**明示指示があるときだけ**（無断で横断しない）
- **公式採用ページを最優先**の一次情報にしつつ、**就活サイト（マイナビ／リクナビ／ワンキャリア 等）も積極的に併用**して今年度・過去の情報を拾う。食い違いは**公式優先＋出典明記**
- **予測は必ず「予測（昨年実績ベース）」と明示**し、根拠（過去の実日付）を併記する。確定情報と峻別し、断定・捏造しない
- **締切は流動的**。取得日を必ず併記し「最新は必ず公式採用ページで確認」を明示。締切超過の誤認は致命的なので、不確かなものは「**要確認**」にする
- **捏造しない**。取れない情報は空欄／「未公表」「要確認」。それらしい日付・内容をでっち上げない
- **非公式（口コミ・倍率・難易度）は複数ソースで裏取り**
- **カバレッジを honest に報告**：取得できたイベント数・参照した情報源、未取得／未発表の別を必ず示す
- 個人情報・マイページのログイン情報はローカルに留め、外部サービスへ送らない
- 成果物は `work/recruit/` に置く（`office/` 配下に書かない）
