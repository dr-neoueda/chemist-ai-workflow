# caw-events — 就活イベント・募集情報カタログ

就活モードのイベント収集スキル。**業界横断で多数企業のインターン・企業説明会・座談会・選考イベントを詳細に集め**、イベントカタログ・締切カレンダー・企業比較表にまとめ、秘書の選考スケジュールに連携する。`caw-research`（個社研究）・秘書（スケジュール管理）の上に乗る横断レイヤー。**締切収集はこのスキルの一部**（イベントの中身まで含めて集めるのが本スキル）。

## いつ使うか

- `/caw-events` を実行したとき
- 「○○業界のインターン情報を集めて」「説明会・選考イベントをまとめて」「就活イベントをカタログにして」「締切だけでなくインターンの中身も知りたい」と言われたとき
- `caw-research` の業界研究の後に「この業界の募集・イベントも集めて」と言われたとき

`office/`（就活モード）が無ければ `/caw` で就活トラックのセットアップを促す。企業・業界研究部 / 秘書部が未作成なら作成を提案する。

## はじめてモードを尊重する

このスキルを実行する前に `office/CLAUDE.md`（Codex CLI / GitHub Copilot CLI では `AGENTS.md`）を読み、冒頭に `> 運用モード: はじめて` があれば、`caw` skill の「はじめてモードの挙動」を全応答に適用する：**平易な日本語**で話し、専門用語（インターン・オープンカンパニー・早期選考・本選考直結 等）は初出で 1 行説明を添え、各ステップの最後に**「次はこれをしましょう」を 1 つ**だけ提示する。

## ワークフロー

### Step 1: 対象を確認（不足は `AskUserQuestion`）

- **対象**：業界（例: エネルギー業界）／または企業リスト
- **集めるイベント種別**：インターン／オープンカンパニー・1day／企業説明会・セミナー／座談会・OB/OG訪問会／本選考（既定: **すべて**）
- **対象シーズン**：例「27卒・2026年夏」（年度で変わるため必須）
- 任意：職種（事務系/技術系/DS 等）・地域・**件数規模**（例: 主要20社）

### Step 2: 企業リストを確定

- 業界指定なら、`companies/_industry/<業界>.md`（業界研究があれば）または web 検索で**主要企業を列挙**し、ユーザーに追加／除外してもらう
- 大規模時は**志望度・規模で優先順位**を付け、上位から着手（残りは段階収集）。対象社数 M を確定させる

### Step 3: 詳細収集（一次情報優先・公式＋ナビ横断）

各イベントについて、取れた範囲で次を集める（取れない項目は空欄/「要確認」）：

| 項目 | 例 |
|---|---|
| 企業 / 種別 | インターン / オープンカンパニー / 説明会 / 座談会 / 本選考 |
| 名称・テーマ | 「データサイエンスWS」「事業立案体感ワーク」 |
| 職種・コース | 事務系 / 技術系 / データサイエンス / 電気 |
| 形式・日数・場所 | 対面 / オンライン、1day / 2日 / 5日、本社 / 各拠点 |
| 対象 | 学年・専攻・卒業年度（例: 27卒・院/学部） |
| 応募締切・実施日 | `2026-06-26` 締切 / 実施 `8/6-7` |
| 優遇・早期選考 | 早期選考あり / 本選考直結 / 優遇ルート |
| 報酬・交通費 | 日当 / 交通費 / 宿泊の有無 |
| 選考 | ES / 適性検査 / 面接 / 抽選 / 先着 |
| 口コミ・倍率 | 参加者の声・倍率（**非公式は複数ソースで裏取り**・出典必須） |
| 出典・取得日・状態 | URL・`2026-06-13`・公表済 / 要確認 / 未公表 |

**ソースの優先順位**：① 公式採用ページ・マイページ告知（一次情報）→ ② ナビサイト（マイナビ/リクナビ等）・就活情報（ワンキャリア/外資就活/unistyle 等、出典併記の補助）。

- **ログイン必須・未公表で取れない情報は捏造しない**。「要確認」に分離し、確認導線（公式採用ページURL）を残す
- 締切は流動的 → **取得日を必ず併記**し「最新は公式で確認」を明示
- **口コミ・倍率・選考難易度などの非公式情報は 2 ソース以上で裏取り**（公式は単一可）。出典が割れたら幅・年度を併記

### Step 4: イベントカタログに構造化保存

`recruit/<業界slug>.md` に **1 イベント = 1 ブロック**で保存（上記項目を見出し付きで）。

- 冒頭に**カバレッジ**（取得イベント数・対象社数 N/M・取得日）と、締切が近い順のサマリ
- 「要確認」「未公表」を明示。**再実行時は差分更新**（新規イベント・締切変更・募集終了を検知）

### Step 5: HTML 3ビュー（実行時に `AskUserQuestion` で選択）

`recruit/<業界slug>.html`（既定は 3 ビュー同梱、要望に応じて個別ファイル）。**`caw-research` の HTML 可視化規約を踏襲**する：

- **① イベントカタログ**：イベントを**カード一覧**で表示。種別・職種・形式・月で**フィルタ**。各カードに締切・実施日・優遇/早期選考・出典・取得日
- **② 締切カレンダー**：タイムライン／月別ガント（**締切が近いほど色を強める**）。直近の山が一目で分かるように
- **③ 企業 × イベント比較表**：行=企業、列=イベント種別や属性（優遇/早期選考/本選考直結/報酬/選考有無）の**有無マトリクス**
- チャートは**オフライン自己完結（SVG）/ Chart.js** を選択。**見出しアンカー id と `<canvas id>` は別名**（`ch` 接頭辞）。Chart.js は固定サイズ or `responsive`＋高さ固定。各カード/行に**出典リンク＋取得日**、「要確認」は視覚的に区別

### Step 6: 秘書の選考スケジュールへ連携

- 締切・実施日（特に直近・志望度の高いもの）を `secretary/todos/YYYY-MM-DD.md` の選考スケジュールに**反映を提案**
- Notion 等の TODO を併用していれば秘書ルールの双方向同期に従う
- 締切が近い順に提示して**抜け漏れを防止**。差分（締切変更・締切間近）はアラート

## 大規模収集のコツ

- バッチで企業群を回し、1 社ずつ「種別 × イベント × 属性 × 出典」を埋める
- 件数が多いときは「**公表済み**」と「**要確認**」を分け、**カバレッジ（取得イベント数・N/M 社・未取得社一覧）を必ず報告**する。無音の取りこぼし禁止
- 締切が密集する時期（夏インターン=6〜8月、本選考=2〜4月 など）はカレンダーで山を見せると判断しやすい
- 同業界は前年と日程・コース構成が似る → 前年実績は「参考（昨年）」として併記可（**要確認**を明示）

## 重要な注意事項

- **締切は流動的**。取得日を必ず併記し「最新は必ず公式採用ページで確認」を明示。締切超過の誤認は致命的なので、不確かなものは「**要確認**」にする
- **捏造しない**。取れない情報は空欄／「未公表」「要確認」。それらしい日付・内容をでっち上げない
- **一次情報優先**：公式採用ページ ＞ ナビサイト ＞ 口コミ。**口コミ・倍率などの非公式は複数ソースで裏取り**
- **カバレッジを honest に報告**：取得できたイベント数 / 社数、未取得社の一覧を必ず示す
- 個人情報・マイページのログイン情報はローカルに留め、外部サービスへ送らない
- 成果物は top-level `recruit/` に置く（`office/` 配下に書かない）
