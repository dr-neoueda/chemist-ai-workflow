# caw-intake — 過去書類の取り込み・自己分析ジェネレータ

就活モードの取り込みスキル。過去に書いた応募書類を `documents/inbox/` に入れて発火すると、本人の**文体・経験・強み/弱み・ガクチカ・志望動機/就活の軸・プロフィール・過去回答**を抽出し、それぞれ適切なファイルに整理する。これにより caw-es / caw-interview が「本人の言葉・本人の実績」で書けるようになる。

## いつ使うか

- `/caw-intake` を実行したとき
- 「過去の ES を取り込んで」「inbox の文章から自己分析して」「私が書いたものを読み込んで」「文体と経験を抽出して」と言われたとき
- 就活を始めた直後で、過去に書いた書類（ES・志望動機・自己PR・履歴書）が手元にあるとき

`office/`（就活モード）が無ければ `/caw` で就活トラックのセットアップを促す。

## はじめてモードを尊重する

このスキルを実行する前に `office/CLAUDE.md`（Codex CLI / GitHub Copilot CLI では `AGENTS.md`）を読み、冒頭に `> 運用モード: はじめて` があれば、`caw` skill の「はじめてモードの挙動」を全応答に適用する：**平易な日本語**で話し、専門用語（ガクチカ・STAR・自己分析 等）は初出で 1 行説明を添え、各ステップの最後に**「次はこれをしましょう」を 1 つ**だけ提示する。

## ワークフロー

### Step 1: 入力を集める

- `documents/inbox/` の文章（ES・志望動機・自己PR・ガクチカ・履歴書・職務経歴書 等。`.md` / `.txt` / `.docx` / `.pdf`）をすべて読む
- **空なら**「過去に書いた ES や志望動機を `documents/inbox/` に入れてから、もう一度『取り込んで』と言ってください」と促して終了
- 1 件でもあれば、**何件・どんな書類があったか**を最初に報告してから次へ
- 画像 PDF などテキストを取り出せない場合は、その旨を伝えてテキスト化（コピペや書き起こし）を促す

### Step 2: 抽出して各ファイルへ書き分ける

読み取った内容から次を抽出し、**それぞれ適切なファイルに追記マージ**する（既存があれば上書きせず、重複を避けて統合）。`self-analysis/` が無ければ作成する。

| 抽出するもの | 書き出し先 | 中身 |
|---|---|---|
| 文体プロファイル | `documents/voice-style.md` | トーン（です・ます/だ・である）・一文の長さ・よく使う語彙と言い回し・論理展開（結論先出しか）・構成の癖・避ける表現 |
| 経験（STAR 化） | `self-analysis/experiences.md` | 1 経験 1 ブロックで「状況 / 課題 / 行動 / 結果」。数値・固有名詞も拾う |
| 強み・弱み・価値観 | `self-analysis/strengths.md` | 繰り返し現れる強み、弱み（短所）＋改善努力、価値観・モチベーションの源 |
| ガクチカ候補 | `self-analysis/gakuchika.md` | 「学生時代に力を入れたこと」の核になる題材（題材名＋一言要約） |
| 志望動機・就活の軸 | `self-analysis/motivation.md` | なぜこの業界/職種か・就活の軸・will/can/must・キャリアビジョン（将来像）・原体験 |
| 基本プロフィール | `self-analysis/profile.md` | 氏名・連絡先・学歴・専攻/研究・資格・語学スコア（TOEIC 等）・スキル・趣味/特技・課外活動 |
| 過去回答バンク | `documents/past-answers.md` | 過去に書いた「設問 × 完成回答」を設問タイプ別にカタログ化（流用・参考用。応募先に合わせて作り直す前提） |

- 各ファイルは**見出し付きの Markdown** にし、後から caw-es / caw-interview が読みやすい構造にする
- 出典が複数 ES にまたがる場合は統合する。**矛盾（同じ経験で数値が違う等）があれば両論併記でユーザーに確認**する
- inbox の原文は素材としてそのまま残す（削除しない）

### Step 3: 確認と次の一歩

- **何を・どのファイルに書いたか**をパス付きの一覧で報告し、各ファイルの要点を 1〜2 行で添える
- 個人情報（氏名・連絡先・学籍番号等）はローカル（`self-analysis/` `documents/`）に留めた旨を明示する
- 次の一歩を 1 つ提示（例:「これで caw-es が本人の文体・実績で ES を書けます。志望企業の ES を書きますか？」）

## caw-es / caw-interview との関係

- **caw-intake は「作る」側、caw-es / caw-interview は「使う」側**。caw-intake が `self-analysis/` と `documents/voice-style.md` を整備し、caw-es はそれを読んで本人の文体・実績で ES を書く。
- caw-es の「文体を学習して」は文体プロファイル（`documents/voice-style.md`）だけを作る軽量版。**経験・強み・ガクチカ・プロフィールまでまとめて抽出するなら caw-intake** を使う。

## 重要な注意事項

- **個人情報はローカルに留める**。`self-analysis/profile.md` 等に氏名・連絡先・学歴・学籍番号を書く場合も、外部サービスへ送る前に必ず確認する
- **既存ファイルは上書きしない**。追記マージし、重複・矛盾は統合またはユーザー確認で解消する
- **事実を歪めない**。inbox の記述をそのまま素材化し、誇張・捏造を足さない
- **文体プロファイルは `documents/voice-style.md` に書き出す**。部署や `office/` の `AGENTS.md`（`CLAUDE.md`）は**書き換えない**（設定と文体・自己分析を分離する）
- 成果物（`self-analysis/` `documents/`）は top-level に置く（`office/` 配下に書かない）
