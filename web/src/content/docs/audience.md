## ターゲット顧客

- **化学・材料・実験系研究者**
  - D 生（博士後期課程）
  - PD（ポスドク）
  - 若手 PI（独立した研究者）

## 想定読者プロフィール

- ChatGPT / Claude.ai / Gemini など AI チャットツールを使った経験がある
- **Claude Code や AI エージェントの分業運用は未経験 / 経験浅くても OK**（このハンドブックは初心者にも段階的に手ほどきする構成）
- Python / シェルは少しでも触れる（プログラマでなくても問題なし、必要なコマンドは都度紹介）
- 何らかの計算化学ソフト（量子化学計算 / 古典 MD / 周期系 DFT 等）を日常的に、あるいは必要に応じて使う ── 具体的なソフトの種類は問わない
- 論文管理、計算管理、執筆、申請書、発表資料のいずれかで時間配分に課題を感じている

つまり、**「AI を本格的に研究で使ってみたいが、何から始めるか・どう組み立てるかが見えない」化学・材料・実験系研究者**が中心ターゲットです。AI エージェントの分業運用に慣れた読者向けの応用編も用意しますが、必須ではありません。

## 解決する 4 つの課題

### 1. 文献管理が散逸する

- 数百本の PDF が Google Drive / Dropbox / OneDrive / ローカルに散らばる
- 「どこかで読んだ気がする」が見つからない
- ナレッジベース（Notion / Obsidian / Logseq など）でデータベース化を試みたが手が回らない

→ **文献部** が PDF → Markdown → **お使いのナレッジベース + クラウドストレージ**に自動登録、要約・タグ付け・引用整理。

**ただし**ツールごとに API / MCP の成熟度とアーキテクチャ（DB ベース vs ファイルベース vault）が異なり、すべての組み合わせが同じ自動化レベルになるわけではありません。著者は **Notion + Google Drive**（両者公式 MCP / API 完備）で運用していますが、Obsidian + Drive のようなファイルベース vault 構成にも展開できます。詳細な対応マトリクスは [対応ツール一覧](/tools/) を参照。

### 2. 計算化学の効率化

- 入力ファイル（`.gjf` / `.inp` / `.mdp` / `.in` など各種）を毎回手書きしている
- log 解析が手作業
- 計算が落ちた理由を毎回ゼロから調べ直している（Hessian 陳腐化、SCF 不収束、cutoff 不足など）

→ **計算管理部** が Playbook（既知の罠と処方）を蓄積、ジョブ生成・監視・解析を半自動化。

**対象は CLI ベースの計算ソフト**（入力ファイルと log がテキスト、shell でジョブが回せるもの）。これらは AI エージェントが読み書き・編集・提出・log 解析を直接扱えるため、方法論がそのまま転用できます：

- **量子化学計算**: Gaussian, ORCA, Q-Chem, Psi4, GAMESS, NWChem ほか
- **古典 MD**: GROMACS, AMBER, NAMD, LAMMPS, OpenMM ほか
- **周期系 DFT / 平面波**: CP2K, VASP, Quantum ESPRESSO, CASTEP, SIESTA ほか

著者の使用ソフトは Gaussian / GROMACS / CP2K のみですが、Playbook の書式・運用パターンは他 CLI ソフトのテンプレートとして転用可能です。

**対象外**（GUI 必須のソフト）：Materials Studio, Discovery Studio, ChemDraw, Schrödinger Maestro の GUI workflow など。これらは AI エージェントによる自動化に向きません。

詳細な対応マトリクスは [対応ツール一覧](/tools/) を参照。

### 3. 論文執筆プロセスで AI を継続的に活用したい

- 単発で文章を生成させて使い捨てている
- 引用整合性、用語統一、reviewer 対応に時間がかかる
- スタイルガイドが投稿先ごとに異なる
- 共著者・指導教員とのドラフトのやり取りで AI を活かしきれていない

→ **論文執筆部** が指導教員の文体プロファイルとターゲット誌のスタイルを保持した状態で、長文の編集と推敲を支援。

**LaTeX / Word の両方に対応**：

- **LaTeX 派**: `.tex` / `.bib` を AI と直接編集（最も自然、★★★）
- **Word 派**: Pandoc 経由で推敲（`.docx` → md → AI → `.docx`）、または python-docx で書式保持の直接編集、Microsoft Graph API でクラウド共著
- **Markdown ハブ**: AI と md で書き、出力時に Pandoc / Quarto で LaTeX or Word に変換（投稿先未定でも両対応可能）

著者環境は LaTeX + BibTeX のみですが、Word 環境の実装パスとサンプルスクリプトも教材で配布予定。詳細は [対応ツール一覧](/tools/) を参照。

### 4. 申請書・発表資料の品質向上

- 学振 DC2 / 科研費 / 学会発表が「自分一人で書いて一度だけ見直す」状態
- 専門外の審査員にも伝わる平易な文章になっているか確認しきれない

→ **申請書執筆部** が指導教員の文体プロファイル + 投稿先のスタイル + 字数制約を保持して、ドラフト・推敲・再投影を継続的に支援。AI を「他分野視点の読者」として常駐させて、書きながらチェックできる状態を作ります。
