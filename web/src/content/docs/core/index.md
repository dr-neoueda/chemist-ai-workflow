## このセクションの目的

特定の AI CLI（Claude Code / Codex CLI / Gemini CLI / ChatGPT）に依存しない、**方法論のレイヤー**を扱います。

- 部署フォルダの設計
- ファイル構造とルール
- TODO / ノート / 意思決定ログのフォーマット
- 部署間の連携と品質ゲート

## 章立て（執筆中）

1. なぜ「部署化」なのか — チャット駆動の限界
2. AI 部署のテンプレート — 最小構成（1〜2 部署）から最大構成（10 部署超）まで、追加・分割・統合の判断基準
3. ファイル命名と日次運用ルール
4. 意思決定ログ（decisions.md）と学び（learnings.md）の書式
5. 部署間連携 — 秘書を窓口にする理由
6. 品質ゲートの組み込み（応用編で AI 二段レビューパターンも扱う）
7. ベンダーロックインを避ける選択

## ステータス
